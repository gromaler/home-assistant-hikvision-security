# Full-Resolution Hikvision Snapshots in Home Assistant

One of the first practical problems in this project was surprisingly simple:

**the camera looked good in live view, but the saved snapshot did not.**

The Hikvision camera was capable of a much higher-resolution main stream, yet snapshots obtained through the normal Home Assistant camera path were only around 640×360 in our test setup.

That was not useful enough for security snapshots, where details matter.

## The problem

The camera exposes multiple video streams.

A typical Hikvision configuration uses URLs such as:

```text
/Streaming/Channels/101
/Streaming/Channels/102
```

For many Hikvision cameras:

- `101` = channel 1, main stream
- `102` = channel 1, sub stream

The exact capabilities depend on the model and firmware.

In our setup, the live/main stream was clearly higher resolution than the JPEG snapshot being returned through the normal integration path.

We also tested Hikvision's HTTP/ISAPI picture endpoint, but it did not solve the resolution problem on this particular camera/firmware combination.

So instead of asking the camera integration for a JPEG, we decided to take a frame directly from the stream we already knew had the desired quality.

## Verify the RTSP main stream

The Hikvision main-stream URL normally follows this pattern:

```text
rtsp://USERNAME:PASSWORD@CAMERA_IP:554/Streaming/Channels/101
```

Example with placeholders:

```text
rtsp://USERNAME:PASSWORD@192.168.1.101:554/Streaming/Channels/101
```

Do not publish a real camera username or password in GitHub.

You can test the stream with FFmpeg:

```bash
ffmpeg -rtsp_transport tcp \
  -i "rtsp://USERNAME:PASSWORD@192.168.1.101:554/Streaming/Channels/101" \
  -frames:v 1 test.jpg
```

FFmpeg also prints information about the detected video stream. This is useful for confirming that you are actually connected to the expected main stream.

In our working setup, FFmpeg reported the Hikvision main stream as HEVC/H.265 at **2560×1440** during testing.

## Home Assistant solution

Instead of using a normal camera snapshot action, we use a Home Assistant `shell_command` that runs FFmpeg and extracts exactly one video frame.

Example:

```yaml
shell_command:
  hikvision_camera_snapshot: >
    ffmpeg -y -rtsp_transport tcp
    -i "rtsp://USERNAME:PASSWORD@192.168.1.101:554/Streaming/Channels/101"
    -frames:v 1
    "/media/cameras/camera_1/camera_{{ now().strftime('%Y%m%d_%H%M%S') }}.jpg"
```

The timestamp makes every snapshot a separate file:

```text
camera_20261002_184501.jpg
camera_20261002_184732.jpg
camera_20261002_190015.jpg
```

This is useful when snapshots are generated by motion, door, gate, or alarm events.

## Allow Home Assistant to use /media

Our configuration includes:

```yaml
homeassistant:
  allowlist_external_dirs:
    - "/media"
```

The example repository stores camera snapshots below:

```text
/media/cameras/
```

with one directory per camera:

```text
/media/cameras/
├── camera_1/
├── camera_2/
└── camera_3/
```

Create the directories before trying the snapshot commands.

## Test from Home Assistant

After adding the `shell_command` configuration, restart Home Assistant.

Then open:

**Developer Tools → Actions**

Run:

```text
shell_command.hikvision_camera_snapshot
```

A new JPEG should appear in the configured directory.

If it does not, check the Home Assistant logs and test the same RTSP URL with FFmpeg from the Home Assistant terminal.

## Why use TCP?

The command contains:

```text
-rtsp_transport tcp
```

For this installation, TCP proved to be a straightforward and reliable way to request the RTSP stream for snapshot capture.

For a single-frame security snapshot, reliability is more important than shaving a tiny amount of latency from the connection.

## Automatic cleanup

Snapshots can accumulate quickly.

A simple Home Assistant shell command can remove JPEG files older than seven days:

```yaml
shell_command:
  cleanup_hikvision_snapshots: >
    find /media/cameras
    -type f \( -iname "*.jpg" -o -iname "*.jpeg" \)
    -mtime +7 -delete
```

`find` searches the subdirectories recursively, so the camera directories remain intact while old JPEG files are removed.

Before using `-delete`, you can preview the matching files in the Home Assistant terminal:

```bash
find /media/cameras -type f \( -iname "*.jpg" -o -iname "*.jpeg" \) -mtime +7
```

To remove **all** JPEG snapshots recursively while keeping the directory structure:

```bash
find /media/cameras -type f \( -iname "*.jpg" -o -iname "*.jpeg" \) -delete
```

## Why not just use the low-resolution snapshot?

For a dashboard thumbnail, a small JPEG may be perfectly adequate.

For a security event, however, the extra detail can matter. A higher-resolution frame can provide a better view of a person, vehicle, object, or other detail in the scene.

The important point is that FFmpeg is not magically increasing image resolution. It simply captures a frame from the higher-resolution RTSP stream that the camera is already producing.
